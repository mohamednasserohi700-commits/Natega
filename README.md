# موقع نتيجة الثانوية العامة (Flask) - System Makers

موقع احترافي، الطالب يدخل رقم الجلوس ويظهرله الاسم والمجموع الكلي وحالته، بناءً على قاعدة بيانات مبنية من ملف الإكسيل الحقيقي.

## محتويات المشروع
```
result_app/
├── app.py                 # كود التطبيق الرئيسي (Flask + SQLite)
├── db_parts/                # أجزاء قاعدة البيانات (5 ملفات، كل واحد أقل من 25 ميجا)
├── build_db.py               # سكريبت لإعادة بناء students.db من ملف إكسيل جديد
├── split_db.py                # سكريبت لتقسيم students.db لأجزاء صغيرة (لو حجمه كبير)
├── requirements.txt           # المكتبات المطلوبة وقت التشغيل
├── Procfile                   # أمر تشغيل السيرفر على Railway
├── .gitignore                  # يستثني students.db (بيتبني تلقائي من db_parts)
├── templates/
│   ├── index.html              # صفحة البحث
│   ├── result.html              # صفحة عرض النتيجة
│   └── results_list.html         # صفحة نتائج البحث بالاسم (لو أكتر من طالب)
└── static/
    └── style.css                  # التنسيق
```

## ⚠️ مهم جدًا: طريقة الرفع على GitHub

ملف قاعدة البيانات الأصلي `students.db` حجمه ~97 ميجا، وده **أكبر من حد الرفع بالسحب والإفلات على GitHub (25 ميجا)**. عشان كده:

1. **قسّمت الملف لك مسبقًا** لمجلد `db_parts/` (5 أجزاء، كل جزء ~20 ميجا).
2. **الموقع بيجمّع الأجزاء دي تلقائيًا** ويبني `students.db` وحده أول ما السيرفر يشتغل على Railway - مش محتاج تعمل أي حاجة يدوي.
3. **لما ترفع المشروع على GitHub، ارفع مجلد `db_parts` كامل بكل الأجزاء اللي جواه**، ومتحاولش ترفع `students.db` نفسه (أصلًا مستبعد في `.gitignore`).

### أفضل طريقة للرفع (تحل مشكلة حجم الملف ومشكلة هيكل المجلدات مع بعض)
لو معاك حاسبك، استخدم أوامر `git` بدل السحب والإفلات من المتصفح - أسهل، أضمن، وبيسمح لحد 100 ميجا للملف الواحد من غير أي تقسيم:
```bash
cd result_app
git init
git add .
git commit -m "أول نسخة من موقع النتيجة"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```
(استبدل `USERNAME/REPO_NAME` بمستودعك على GitHub)

### لو هتكمل بالسحب والإفلات من المتصفح
- ارفع كل الملفات والمجلدات **بما فيها `templates/` و`static/` و`db_parts/`** كمجلدات، مش ملفات لوحدها في الروت (المتصفحات الحديثة زي Chrome بتحافظ على هيكل المجلد لو سحبته كامل).
- اتأكد بعد الرفع إن هيكل الملفات على GitHub مطابق تمامًا للي في القايمة فوق (يعني فيه مجلد `templates` فيه 3 ملفات، مش الملفات دي متبعثرة في الروت).

## تحديث قاعدة البيانات لملف جديد (سنة جديدة مثلاً)
```bash
pip install pandas openpyxl
python build_db.py path/to/new_students.xlsx   # يبني students.db جديد
python split_db.py                              # يقسمه لأجزاء في db_parts/ لو حجمه أكبر من 25 ميجا
```
بعدها ارفع مجلد `db_parts` المحدّث على GitHub.

## ليه SQLite مش Excel مباشرة؟
ملفك الأصلي فيه **919,396 طالب** (40 ميجا)، وتحميله بـ pandas مباشرة كان بياخد **~40 ثانية** في كل مرة. عشان كده حولناه لقاعدة بيانات SQLite مفهرسة (indexed) على رقم الجلوس، فبقى البحث **فوري (أقل من مللي ثانية)** بدل ما يبطّئ الموقع.

## طرق البحث المتاحة
- **برقم الجلوس**: نتيجة فورية ودقيقة 100%.
- **باسم الطالب**: اكتب 3 أحرف على الأقل من الاسم.
  - لو الاسم طابق طالب واحد بس، هتنقله لصفحة النتيجة مباشرة.
  - لو طابق أكتر من طالب (زي الأسماء المتشابهة)، هتظهر قائمة بكل النتائج المطابقة (حتى 30 نتيجة) يختار منها الطالب المطلوب.

## التقدير العام
المجموع الكلي من **320 درجة**، والتقدير بيتحسب تلقائيًا من النسبة المئوية:

| النسبة | التقدير |
|---|---|
| 85% فأكثر | ممتاز |
| 75% إلى أقل من 85% | جيد جدًا |
| 65% إلى أقل من 75% | جيد |
| 50% إلى أقل من 65% | مقبول |
| أقل من 50% | ضعيف |

لو عايز تغيّر النسب دي أو المجموع الأقصى (لو مختلف عن 320 في ملف تاني)، عدّل المتغيرات `MAX_TOTAL` و`GRADE_BANDS` في أول ملف `app.py`.

## أعمدة البيانات
الأعمدة الحقيقية في ملفك:

| seating_no | arabic_name | total_degree | student_case_desc |
|---|---|---|---|
| 2001970 | احمد محمود السيد... | 290.0 | ناجح دور أول |

عمود `student_case_desc` فيه 4 حالات مختلفة، وكل واحدة بتظهر بشكل ولون مختلف في الموقع:
| القيمة في الملف | يظهر في الموقع كـ |
|---|---|
| ناجح دور أول | ✅ ناجح (أخضر) |
| دور ثان | ⚠️ دور ثانٍ (برتقالي) |
| راسب دور أول | ❌ راسب (أحمر) |
| غياب كلى دور أول | ⚪ غياب كلي (رمادي) |

## تحديث البيانات لملف جديد (سنة جديدة مثلاً)
لما يجيلك ملف نتيجة جديد بنفس الأعمدة دي بالظبط، شغّل:
```bash
pip install pandas openpyxl
python build_db.py path/to/new_students.xlsx
```
هيعمل ملف `students.db` جديد بمكان القديم. لو حجمه أكبر من 25 ميجا، شغّل `python split_db.py` كمان عشان يقسمه لأجزاء، وارفع (`push`) مجلد `db_parts` المحدّث على GitHub وRailway هيعمل Redeploy تلقائيًا.

## التشغيل محليًا (على جهازك)
```bash
cd result_app
pip install -r requirements.txt
python app.py
```
هيشتغل على: http://127.0.0.1:5000

## النشر على Railway
1. اعمل حساب على [railway.app](https://railway.app) (تقدر تسجل دخول بحساب GitHub).
2. ارفع مجلد المشروع ده (شامل مجلد `db_parts` بكل الأجزاء اللي جواه) على مستودع GitHub جديد (repo).
   - الموقع هيجمّع `students.db` تلقائيًا من الأجزاء دي أول ما يشتغل، مش محتاج ترفع `students.db` نفسه.
3. من لوحة تحكم Railway: **New Project → Deploy from GitHub repo** واختار الريبو.
4. Railway هيكتشف تلقائيًا إن المشروع Python وهيستخدم ملف `Procfile` لتشغيل السيرفر باستخدام `gunicorn`.
5. مفيش أي متغيرات بيئة (Environment Variables) مطلوبة، Railway بيحدد رقم البورت تلقائيًا عن طريق متغير `PORT` والكود متظبط عليه بالفعل.
6. بعد ما يخلص الـ Deploy، هتلاقي رابط مباشر للموقع من تبويب **Settings → Domains → Generate Domain**.
