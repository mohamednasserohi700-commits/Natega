# موقع نتيجة الثانوية العامة (Flask) - System Makers

موقع احترافي، الطالب يدخل رقم الجلوس ويظهرله الاسم والمجموع الكلي وحالته، بناءً على قاعدة بيانات مبنية من ملف الإكسيل الحقيقي.

## محتويات المشروع
```
result_app/
├── app.py                 # كود التطبيق الرئيسي (Flask + SQLite)
├── students.db             # قاعدة بيانات الطلاب (مبنية من ملفك الحقيقي - 919,396 طالب)
├── build_db.py              # سكريبت لإعادة بناء students.db من ملف إكسيل جديد
├── requirements.txt         # المكتبات المطلوبة وقت التشغيل
├── Procfile                 # أمر تشغيل السيرفر على Railway
├── templates/
│   ├── index.html           # صفحة البحث
│   └── result.html          # صفحة عرض النتيجة
└── static/
    └── style.css              # التنسيق
```

## ليه SQLite مش Excel مباشرة؟
ملفك الأصلي فيه **919,396 طالب** (40 ميجا)، وتحميله بـ pandas مباشرة كان بياخد **~40 ثانية** في كل مرة. عشان كده حولناه لقاعدة بيانات SQLite مفهرسة (indexed) على رقم الجلوس، فبقى البحث **فوري (أقل من مللي ثانية)** بدل ما يبطّئ الموقع.

## طرق البحث المتاحة
- **برقم الجلوس**: نتيجة فورية ودقيقة 100%.
- **باسم الطالب**: اكتب 3 أحرف على الأقل من الاسم.
  - لو الاسم طابق طالب واحد بس، هتنقله لصفحة النتيجة مباشرة.
  - لو طابق أكتر من طالب (زي الأسماء المتشابهة)، هتظهر قائمة بكل النتائج المطابقة (حتى 30 نتيجة) يختار منها الطالب المطلوب.

## التقدير العام
المجموع الكلي من **320 درجة**، والتقدير بيتحسب تلقائيًا من النسبة المئوية:

| النسبة | التقدير |
|---|---|
| 85% فأكثر | ممتاز |
| 75% إلى أقل من 85% | جيد جدًا |
| 65% إلى أقل من 75% | جيد |
| 50% إلى أقل من 65% | مقبول |
| أقل من 50% | ضعيف |

لو عايز تغيّر النسب دي أو المجموع الأقصى (لو مختلف عن 320 في ملف تاني)، عدّل المتغيرات `MAX_TOTAL` و`GRADE_BANDS` في أول ملف `app.py`.

## أعمدة البيانات
الأعمدة الحقيقية في ملفك:

| seating_no | arabic_name | total_degree | student_case_desc |
|---|---|---|---|
| 2001970 | احمد محمود السيد... | 290.0 | ناجح دور أول |

عمود `student_case_desc` فيه 4 حالات مختلفة، وكل واحدة بتظهر بشكل ولون مختلف في الموقع:
| القيمة في الملف | يظهر في الموقع كـ |
|---|---|
| ناجح دور أول | ✅ ناجح (أخضر) |
| دور ثان | ⚠️ دور ثانٍ (برتقالي) |
| راسب دور أول | ❌ راسب (أحمر) |
| غياب كلى دور أول | ⚪ غياب كلي (رمادي) |

## تحديث البيانات لملف جديد (سنة جديدة مثلاً)
لما يجيلك ملف نتيجة جديد بنفس الأعمدة دي بالظبط، شغّل:
```bash
pip install pandas openpyxl
python build_db.py path/to/new_students.xlsx
```
هيعمل ملف `students.db` جديد بمكان القديم. بعدها ارفع (`push`) التحديث على GitHub وRailway هيعمل Redeploy تلقائيًا.

## التشغيل محليًا (على جهازك)
```bash
cd result_app
pip install -r requirements.txt
python app.py
```
هيشتغل على: http://127.0.0.1:5000

## النشر على Railway
1. اعمل حساب على [railway.app](https://railway.app) (تقدر تسجل دخول بحساب GitHub).
2. ارفع مجلد المشروع ده (شامل ملف `students.db`) على مستودع GitHub جديد (repo).
   - ملحوظة: ملف `students.db` حجمه ~100 ميجا، تأكد إن الـ repo يقبل الحجم ده (GitHub بيسمح لحد 100 ميجا للملف الواحد عادي بدون Git LFS).
3. من لوحة تحكم Railway: **New Project → Deploy from GitHub repo** واختار الريبو.
4. Railway هيكتشف تلقائيًا إن المشروع Python وهيستخدم ملف `Procfile` لتشغيل السيرفر باستخدام `gunicorn`.
5. مفيش أي متغيرات بيئة (Environment Variables) مطلوبة، Railway بيحدد رقم البورت تلقائيًا عن طريق متغير `PORT` والكود متظبط عليه بالفعل.
6. بعد ما يخلص الـ Deploy، هتلاقي رابط مباشر للموقع من تبويب **Settings → Domains → Generate Domain**.

## فحص سريع للسيرفر
فيه مسار `/health` بيرجع عدد الطلاب في القاعدة، تقدر تستخدمه للتأكد إن كل حاجة شغالة بعد الـ Deploy:
```
https://your-app.up.railway.app/health
```
